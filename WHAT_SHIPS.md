# WHAT_SHIPS — Hathor Red live capability snapshot

Last updated: 2026-09-12 (dose-1.61 analyticsService counts toNonNegInt bar).

## Ships today

- **Auth**: email/password + JWT. No OAuth routes mounted. `authMiddleware` normalizes `req.user` to `{ userId, username }` (same shape as `streamAuth`) and rejects stream-typed tokens on the Bearer path. **dose-1.27**: `authMiddleware` requires finite positive integer `userId` (reject NaN/0/negative/non-integer before `req.user` is set), matching the stream-token bar from dose-1.26. **dose-1.38**: `authMiddleware` uses shared `toPositiveInt` from `streamToken` (DRY with streamAuth path/Bearer checks). **dose-1.39**: Socket.IO handshake uses the same bar (reject `typ === 'stream'`, require positive-int `userId` before `socket.userId` is set).
- **Playback (Dose 1 core)**: signed stream URLs (`GET /api/songs/:id/stream-url` → `/stream?t=…`) so HTML5 `<audio src>` works without Authorization headers. `streamAuth` + `streamToken` (short-lived, song-scoped). streamAuth normalizes `req.user` to `{ userId, username }`, rejects stream-typed tokens on the Bearer path, and requires `songId`/`userId` on query tokens. **dose-1.24**: stream tokens optionally carry `username` from the minting session so `req.user.username` is populated on the query-token path without a DB lookup. **dose-1.26**: `signStreamToken` / `verifyStreamToken` require finite positive integer `userId` and `songId` (reject NaN/0/negative/string junk before `req.user` is set). **dose-1.28**: when `?t=` is present and the route has `:id`, `streamAuth` rejects the request if `token.songId` does not match the path param (defense in depth; `streamSong` still re-checks). **dose-1.29**: `getStreamUrl` and `streamSong` call `toPositiveInt` on path `:id` before DB or token mint and return 400 on invalid ids (same bar as tokens; independent of validation middleware order). **dose-1.30**: `getSongById` also applies `toPositiveInt` on path `:id` and returns 400 on invalid ids (same bar as stream endpoints). **dose-1.31**: `recordListening` applies `toPositiveInt` on body `songId` (and non-negative integer duration) before DB insert (same bar; independent of validation middleware). **dose-1.32**: `updatePlaybackState` applies `toPositiveInt` on body `currentSongId` when present and non-null (null still clears; same bar before DB upsert). **dose-1.33**: `updatePlaybackState` applies bounded finite checks on `position` (0–7200), `volume` (0–1), and `playbackSpeed` (0.25–4) when present (reject NaN/Infinity/out-of-range before DB upsert; omitted keys still leave prior values). **dose-1.34**: `updatePlaybackState` requires strict boolean `isPlaying` when present (reject string/number/null); `recordListening` bounds `duration` to 0–7200 (same ceiling as position). **dose-1.35**: `updatePlaybackState` bounds `pitchShift` to finite [-24, 24] when present (explicit null clears) and requires `stemsConfig` to be null or a plain object (reject arrays/primitives); pitch/stems UI still does not ship. **dose-1.36**: `updatePlaybackState` uses CASE flags for `pitch_shift` / `stems_config` so explicit null actually writes NULL (COALESCE could not clear); validation helpers return `'INVALID'` for bad present values and omit the CASE flag when the key is absent. **dose-1.37**: `streamAuth` path `:id` match and Bearer `userId` normalization both use shared `toPositiveInt` (DRY with token/controller bar). **dose-1.39**: socket `sync-state` applies the same positive-int / bounded / strict-boolean bar before DB upsert + Redis write (throttle 4/s); invalid payloads are dropped silently. **dose-1.40**: socket `room-control` uses shared `toPositiveInt` for `roomId`/`songId` and bounds `position` to finite [0, 7200] before DB update (same bar as sync-state / HTTP playback; invalid position/songId emits error and skips write). **dose-1.41**: remaining socket room handlers (`join-room`, `leave-room`, `request-room-state`, `room-reaction`, `room-chat`, RTC relay, `getRoomPresenceRoster`) use shared `toPositiveInt` for `roomId`/`targetUserId` (same bar as room-control; reject NaN/0/negative before presence or DB work). **dose-1.42**: HTTP `roomController` path handlers (`getRoomById`, `joinRoom`, `leaveRoom`, `deleteRoom`) apply shared `toPositiveInt` on `:id` and return 400 on invalid ids (same bar as socket room path; independent of validation middleware). **dose-1.43**: HTTP `playlistController` path handlers (`getPlaylistById`, `deletePlaylist`, `removeSongFromPlaylist`, `reorderPlaylistSongs`) and body ids (`addSongToPlaylist` playlistId/songId) apply shared `toPositiveInt` and return 400 on invalid ids (same bar as room/song controllers). **dose-1.44**: HTTP `socialController` path handlers (`getComments`, `addComment` song `:id`; `deleteComment` comment `:id`) apply shared `toPositiveInt` and return 400 on invalid ids (same bar as playlist/room/song controllers). **dose-1.45**: HTTP `discoveryController` path handler (`similar` song `:id`) applies shared `toPositiveInt` and returns 400 on invalid ids (same bar as social/playlist/room/song controllers). **dose-1.46**: HTTP `mediaController` path handlers (`getPipeline`, `getWaveform`, `getHlsMaster`, `getHlsResource`, `reprocessSong` song `:id`; `getJobStatus` job `:id`) apply shared `toPositiveInt` and return 400 on invalid ids (same bar as discovery/social/playlist/room/song controllers). **dose-1.47**: HTTP `commerceController` path/query/body ids (`updateProduct` product `:id`; `listTiers` artist `:id`; `cancelSubscription` subscription `:id`; `setEarlyAccess` song `:id`; `listProducts` query songId/artistId; `getRevenue` query artistId; `createProduct`/`requestDownloadToken` body songId) and `intelController` path/query ids (`getSongRetention` song `:id`; `resolveArtistScope` query artistId used by overview/top-tracks/geography/revenue-by-track) apply shared `toPositiveInt` and return 400 on invalid ids (same bar as media/discovery/social/playlist/room/song controllers). **dose-1.48**: HTTP `aiController` path handler (`getSimilarSongs` song `:songId`) applies shared `toPositiveInt` and returns 400 on invalid ids (same bar as discovery/social/playlist/room/song controllers). **dose-1.49**: HTTP `songController.uploadSong` validates body `duration` as finite integer [1, 7200] and optional `year` as finite integer [1900, 2100] before DB insert (same bar as recordListening / position; reject NaN/0/negative/out-of-range; no more raw `parseInt` into songs.duration/year). **dose-1.50**: `uploadSong` resolves optional `genre` via the same `resolveAllowedGenre` / `ALLOWED_GENRES` bar as `getSongs` (case-insensitive; reject unknown; empty/omitted stays null) and trims title/artist/album before insert so Home genre filter and uploads stay aligned. **dose-1.51**: HTTP `privacyController.myAuditTrail` applies shared `toPositiveInt` on query `limit` (default 100, ceiling 500; reject NaN/0/negative/non-integer with 400) so the audit path matches the stream/playback id bar. **dose-1.52**: HTTP `songController.getSongs` / `getMySongs` apply finite positive-int `limit` (default + MAX_PAGE_LIMIT ceiling) and non-negative integer `offset` (default 0); reject NaN/0/negative/non-integer when present with 400 (same bar as privacy audit limit / stream ids; no more raw `parseInt` that coerced junk to defaults). **dose-1.53**: HTTP `discoveryController.search` / `similar` apply finite positive-int `limit` (search default 20 / similar default 10, ceiling 50); reject NaN/0/negative/non-integer when present with 400 (same bar as getSongs / privacy audit; no more raw `parseInt` that coerced junk to defaults). **dose-1.54**: HTTP `socialController.getComments` applies finite positive-int `limit` (default 100, ceiling 500) and non-negative integer `fromMs`/`toMs` (fromMs default 0; toMs optional); reject NaN/negative/non-integer when present with 400 (same bar as discovery/getSongs/privacy; no more raw `parseInt` that coerced junk to defaults). **dose-1.55**: HTTP `intelController` applies finite positive-int `days` (default 30, ceiling 365) on overview/top-tracks/geography and finite positive-int `limit` (default 10, ceiling 50) on top-tracks; HTTP `aiController` applies finite positive-int `limit` on getRecommendations/semanticSearch/getSimilarSongs (defaults 20/20/10, ceiling 50) and body `songCount` on generatePlaylist (default 10, ceiling 50); reject NaN/0/negative/non-integer when present with 400 (same bar; no more raw `parseInt` that coerced junk to defaults). **dose-1.56**: `eventService.ingestBatch` applies shared `toPositiveInt` on each event `songId` and finite non-negative integer [0, 7_200_000] on optional `positionMs`/`durationMs` (reject NaN/0-songId/negative/non-integer/out-of-range; individual events rejected without failing the batch; same bar as stream/playback ids and position ceiling in ms). **dose-1.57**: HTTP `playlistController.generateAIPlaylist` applies finite positive-int `songCount` (default DEFAULT_AI_PLAYLIST_SIZE, ceiling MAX_AI_PLAYLIST_SIZE; reject with 400) matching `aiController.generatePlaylist`; HTTP `roomController.createRoom` applies finite positive-int `maxListeners` (default DEFAULT_ROOM_MAX_LISTENERS, ceiling MAX_ROOM_MAX_LISTENERS; reject with 400) instead of raw coercion to 50. **dose-1.58**: `exportService.processExportJob` applies shared `toPositiveInt` on job payload `requestId` (reject NaN/0/negative/non-integer instead of raw `parseInt` that coerced junk). **dose-1.59**: `jobQueue` (`enqueue` priority/maxAttempts/createdBy, `complete`/`fail`/`getJob` jobId, attempts/maxAttempts from DB rows) and `hlsService.resolveHlsPath` assetId apply shared `toPositiveInt` (reject NaN/0/negative/non-integer instead of raw parseInt). **dose-1.60**: `commerceService` (`resolveChargeAmount` price/min/requested, `chargeAndFinalize` purchase.amount_cents, `subscribe` tier.price_cents, `revenueSummary` entries/totalCents) uses shared `toNonNegInt` (finite non-negative integer; allow 0; reject NaN/negative/non-integer instead of raw parseInt). **dose-1.61**: `analyticsService` (overview/topTracks/songRetention/geography/revenueByTrack counts and duration/bucket/listeners) uses shared `toNonNegInt` from commerceService (finite non-negative integer; allow 0; reject NaN/negative/non-integer instead of raw parseInt).
- **Player**: full `PlayerContext` on main (queue, Fisher-Yates shuffle, repeat, seek guards, play-generation, stream error retry preserves seek, volume/speed, hydrate from `/playback/state`, persist debounce). **Logout clear** (dose-1.20/1.21): when `isAuthenticated` becomes false, `clearQueue()` runs and `hydratedRef` resets so signed streams stop and a later login can hydrate again.
- **Queue UI**: up-next panel, drag reorder (linear only), play-next / makeNext / insertNext (shuffle-aware), dedupe on add.
- **Playlists / Home genre filter / Rooms / Olympus flag gates / Podcasts (soon)** as prior doses.
- **Pitch/stems**: not implemented; UI controls remain hidden.

## Does not ship

- HLS in the live player, OAuth, WebRTC rooms, stem/pitch, cross-device live queue list, podcast catalog.
